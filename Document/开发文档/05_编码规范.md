# 编码规范

> 所属文档：开发文档
> 用途：统一项目编码风格，确保代码可读性和可维护性

---

## 一、Python 版本与风格

| 项目 | 规范 |
|---|---|
| Python 版本 | 3.11 |
| 代码风格 | PEP 8 |
| 格式化工具 | black（line-length=100） |
| Lint 工具 | ruff |
| 类型注解 | 强制要求所有公共函数/方法添加类型注解 |
| 命名规范 | 函数/变量 snake_case，类 PascalCase，常量 UPPER_SNAKE_CASE |
| docstring | Google 风格，所有公共类/函数必须有 docstring |

---

## 二、项目结构规范

```
videocontents/
├── main.py                  # CLI 入口
├── config.py                # 配置管理（M1）
├── config.yaml              # 默认配置
├── requirements.txt         # 依赖清单
├── core/                    # 核心业务模块（M2-M13）
├── adapters/                # 适配层（M15-M17）
├── utils/                   # 工具集（M14）
└── Document/                # 项目文档
```

- 一个模块一个文件，文件名与模块功能对应（snake_case）
- 适配层文件命名：`{类型}_adapter.py`
- 工具集文件命名：按功能拆分（`token_counter.py`、`timestamp.py` 等）

---

## 三、模块开发规范

### 3.1 模块文件结构

每个核心模块文件应包含：
1. 模块 docstring（说明模块职责、依赖、输出）
2. import 分组（标准库 → 第三方 → 本地）
3. 常量定义
4. 数据类定义（dataclass）
5. 异常类定义（如有）
6. 主类/函数定义
7. `if __name__ == "__main__":` 测试入口（可选）

### 3.2 类设计规范

- 每个模块一个主类，类名与模块功能对应（PascalCase）
- 构造函数只做初始化，不做耗时操作（模型加载、文件读取等延迟到方法调用）
- 公共方法必须有类型注解和 docstring
- 私有方法以 `_` 前缀命名

### 3.3 适配层规范

- 每个适配层定义一个抽象基类（ABC），声明统一接口
- 具体适配器继承抽象基类，实现具体第三方库的调用
- 适配器工厂函数 `create_adapter(adapter_type, config)` 根据配置返回具体实例
- 适配器不包含业务逻辑，只做 API 转换和异常包装

## 四、异常处理规范

### 4.1 自定义异常

所有自定义异常继承自项目基类 `VideoContentError`，按模块细分：

```
VideoContentError
├── ConfigError
├── FFmpegError
├── ASRError
├── OCRError
├── LLMError
│   ├── LLMTimeoutError
│   ├── LLMRateLimitError
│   ├── LLMConnectionError
│   ├── LLMContextOverflowError
│   └── LLMResponseParseError
├── OutputError
└── PipelineError
```

### 4.2 异常处理原则

- 不捕获泛化异常（`except Exception:`），只捕获预期的具体异常
- 捕获异常后要么处理，要么包装后重新抛出，不静默吞掉
- 第三方库异常必须包装为项目自定义异常后再抛出
- 致命异常中断流水线，可恢复异常重试，降级异常记录警告后继续

## 五、日志规范

| 级别 | 使用场景 |
|---|---|
| DEBUG | 详细调试信息（变量值、函数入口/出口） |
| INFO | 正常流程信息（阶段开始/完成、处理进度） |
| WARNING | 可恢复问题（重试、降级、时间戳越界） |
| ERROR | 致命错误（模块失败、流水线中断） |

- 日志格式：`%(asctime)s [%(levelname)s] %(name)s: %(message)s`
- 日志文件：`logs/{video_hash}_{timestamp}.log`
- 控制台输出 INFO 及以上，文件输出 DEBUG 及以上

## 六、配置管理规范

- 所有可配置参数集中在 `config.py` 的 dataclass 中定义
- 默认配置在 `config.yaml` 中
- 敏感信息（API Key）从环境变量读取，不硬编码
- 配置参数命名：snake_case，按模块分组（`llm.local.base_url`）

---

## 七、测试规范

### 7.1 单元测试

- 测试文件放在 `tests/` 目录，命名 `test_{模块名}.py`
- 使用 pytest 框架
- 每个公共函数/方法至少一个测试用例
- 适配器使用 Mock 对象测试，不依赖真实第三方库

### 7.2 集成测试

- 端到端测试使用真实视频文件，验证完整流水线
- 测试视频定义在 `tests/fixtures/` 目录
- 验收标准：逐字稿生成成功、知识点非空、题目提取无崩溃、输出目录结构正确

---

## 八、Git 提交规范

- 提交信息格式：`{类型}: {简短描述}`
- 类型：`feat`（新功能）、`fix`（修复）、`docs`（文档）、`refactor`（重构）、`test`（测试）、`chore`（构建/工具）
- 示例：`feat: 添加知识点提取模块`、`fix: 修复ASR时间戳越界问题`、`docs: 更新架构设计文档`
- 一次提交只做一件事，不混合多个不相关的变更
