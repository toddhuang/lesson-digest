## 二、类设计

### 3.1 FrameExtractor 类

```python
class FrameExtractor:
    def __init__(self, config: VideoConfig):
        self.interval = config.frame_interval
        self.default_format = "jpg"
        self.default_quality = 90

    def extract_frames(self, video_path, output_dir, ...) -> List[FrameInfo]
    def extract_frame_at(self, video_path, timestamp, output_path, ...) -> str
```

## 三、核心流程

### 3.1 extract_frames 流程

```
1. 检查视频文件是否存在
2. 确保输出目录存在
3. 构造 ffmpeg 命令（按间隔抽帧）
4. 执行 ffmpeg
5. 扫描输出目录，获取所有生成的图片
6. 按文件名排序（frame_000001.jpg, frame_000002.jpg, ...）
7. 为每张图片计算时间戳：timestamp = index * interval
8. 用 Pillow 读取图片尺寸
9. 返回 FrameInfo 列表
```

### 3.2 ffmpeg 抽帧命令

```python
output_pattern = os.path.join(output_dir, "frame_%06d.jpg")
cmd = [
    "ffmpeg",
    "-i", video_path,
    "-vf", f"fps=1/{interval}",  # 每 interval 秒一帧
    "-q:v", "2",                   # JPG 质量（2=最高）
    "-y",
    output_pattern
]
```

### 3.3 extract_frame_at 流程

```
1. 检查视频文件是否存在
2. 检查 timestamp 是否在视频时长范围内
3. 确保输出目录存在
4. 构造 ffmpeg 单帧提取命令
5. 执行 ffmpeg
6. 返回输出路径
```

### 3.4 单帧提取命令

```python
cmd = [
    "ffmpeg",
    "-ss", str(timestamp),    # 定位到时间点
    "-i", video_path,
    "-vframes", "1",           # 只提取一帧
    "-q:v", "2",
    "-y",
    output_path
]
```

**注意**：`-ss` 放在 `-i` 之前是快速定位（seek），可能不够精确；放在 `-i` 之后是精确解码定位，速度慢。MVP 阶段用快速定位，题目截图后续可优化为精确模式。

## 四、文件命名

- 批量抽帧：`frame_000001.jpg`、`frame_000002.jpg`...

## 五、缓存策略

批量抽帧的图片缓存到 `cache/{video_hash}/frames/` 目录。

缓存键同 M2，基于视频文件 hash。

---

## 六、异常处理

| 异常 | 触发条件 | 处理方式 |
|---|---|---|
| FileNotFoundError | 视频文件不存在 | 抛出 |
| FFmpegError | ffmpeg 执行失败 | 抛出，含 stderr |
| TimestampOutOfRangeError | 时间戳超出视频时长 | 抛出，含有效范围 |
| InvalidVideoError | 视频无视频流 | 抛出 |

---

## 七、性能考虑

- 45分钟视频，30秒间隔 → 约90帧，提取时间 10-20秒
- 抽帧是 IO + 解码操作，速度取决于磁盘和 CPU
- MVP 阶段不做场景变化检测（scene_change_detection=false），后续可加入基于帧差的场景检测
