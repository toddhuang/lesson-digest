# M13 主流程编排模块 — 接口设计

> 所属文档：02_架构设计.md
> 模块编号：M13
> 模块职责：串联所有模块，管理执行顺序、并行控制、断点续传、错误处理

---

## 一、模块概述

主流程编排模块（Pipeline）是系统的核心调度模块，负责串联所有功能模块，管理执行顺序、并行分支控制、断点续传（中间结果缓存）、错误处理和日志记录。是整个流水线的入口和指挥中心。

---

## 二、接口列表

### 13.1 run

**功能**：执行完整的视频处理流水线，返回处理结果。

**签名**：
```python
def run(
    video_path: str,
    output_dir: str,
    config: Config,
    force: bool = False
) -> ProcessResult
```

**输入参数**：
| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| video_path | str | 是 | — | 输入视频文件路径 |
| output_dir | str | 是 | — | 输出根目录 |
| config | Config | 是 | — | 全局配置 |
| force | bool | 否 | False | 是否强制重新处理（忽略缓存） |

**输出**：ProcessResult（完整处理结果）

**异常**：
| 异常类型 | 触发条件 |
|---|---|
| VideoNotFoundError | 视频文件不存在 |
| InvalidVideoError | 视频文件无效（无音轨/无视频流） |
| PipelineError | 流水线执行失败（包含具体失败阶段） |

---

### 13.2 run_stage

**功能**：执行单个阶段（用于调试或断点续传）。

**签名**：
```python
def run_stage(
    stage: str,
    context: PipelineContext,
    config: Config,
    force: bool = False
) -> PipelineContext
```

**输入参数**：
| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| stage | str | 是 | 阶段名称（见阶段列表） |
| context | PipelineContext | 是 | 流水线上下文（含前序阶段结果） |
| config | Config | 是 | 全局配置 |
| force | bool | 否 | 是否强制重新处理 |

**输出**：PipelineContext（更新后的上下文）

**异常**：同 run

---

### 13.3 get_progress

**功能**：获取当前流水线执行进度。

**签名**：
```python
def get_progress() -> PipelineProgress
```

**输入参数**：无

**输出**：PipelineProgress（进度信息）

---

### 13.4 cancel

**功能**：取消当前正在执行的流水线。

**签名**：
```python
def cancel() -> None
```

**输入参数**：无

**输出**：None

## 四、数据结构

### 4.1 PipelineContext（dataclass）

```python
@dataclass
class PipelineContext:
    video_path: str                          # 视频路径
    video_info: Optional[VideoInfo]          # 视频信息（阶段1后填充）
    audio_path: Optional[str]                # 音轨路径（阶段2后填充）
    frame_paths: Optional[List[str]]         # 关键帧路径列表（阶段3后填充）
    frame_timestamps: Optional[List[float]]  # 关键帧时间戳列表（秒），与 frame_paths 一一对应（阶段3后填充）
    asr_results: Optional[List[Sentence]]    # ASR 结果（阶段4后填充）
    ocr_results: Optional[List[OCRFrameResult]]  # OCR 结果（阶段5后填充）
    full_text: Optional[str]                  # 合并全文本（阶段6后填充）
    knowledge_points: Optional[List[KnowledgePoint]]  # 知识点（阶段7后填充）
    problems: Optional[List[Problem]]        # 题目（阶段8后填充）
    screenshot_paths: Optional[List[str]]    # 截图路径（阶段9后填充）
    mindmap_opml: Optional[str]              # 思维导图（阶段10后填充）
    output_files: Optional[OutputFiles]      # 输出文件（阶段11后填充）
    completed_stages: List[str]              # 已完成阶段列表
```

### 4.2 PipelineProgress（dataclass）

```python
@dataclass
class PipelineProgress:
    current_stage: str           # 当前执行阶段
    completed_stages: List[str]  # 已完成阶段
    total_stages: int            # 总阶段数
    progress_percent: float      # 进度百分比（0-100）
    is_running: bool             # 是否正在执行
    is_cancelled: bool           # 是否已取消
    error: Optional[str]         # 错误信息（无错误则为 None）
```

## 五、断点续传机制

### 5.1 缓存策略

每个阶段完成后，将该阶段的输出缓存到本地：
```
cache/{video_hash}/{stage_name}.json
```

### 5.2 缓存键

```
video_hash = md5(video_path + file_size + file_mtime)
```

### 5.3 续传逻辑

执行每个阶段前，检查缓存：
- 缓存存在且 `force=False` → 加载缓存，跳过该阶段
- 缓存不存在或 `force=True` → 执行该阶段，完成后写入缓存

### 5.4 缓存失效

- 视频文件变更（mtime/size 变化）→ 所有缓存失效
- 配置变更（影响输出的参数）→ 相关阶段缓存失效
- `force=True` → 所有缓存失效

## 六、错误处理

### 6.1 错误分级

| 级别 | 处理方式 | 示例 |
|---|---|---|
| 可恢复错误 | 重试（最多5次），成功则继续 | 网络超时、LLM 5xx |
| 降级错误 | 跳过该步骤，记录警告，继续执行 | OCR 某帧失败、截图截错 |
| 致命错误 | 中断流水线，返回错误信息 | 视频无音轨、ASR 模型加载失败 |

### 6.2 错误日志

所有错误记录到日志文件：
```
logs/{video_hash}_{timestamp}.log
```

日志包含：时间、阶段、错误类型、错误信息、堆栈跟踪、重试次数。
