## 一、算法目标

### 1.1 解决的问题

LLM 返回的知识点文字段和题目文字段是**纯文本，没有时间戳**。需要将这些文字段"对齐"回 ASR 原始文本（带字级时间戳），从而精确找到每个知识点/题目在视频中的**起始时间和结束时间**。

### 1.2 精度要求

- **字符级精度**：起始/结束时间精确到具体字符对应的毫秒级时间戳
- 不接受句子级精度（原因：学生看黑板读题时间可能仅1秒，句子级会导致题目截图截到老师已开始板书的画面）

### 1.3 输入

| 输入 | 来源 | 格式 |
|---|---|---|
| ASR 原始句子列表 | FunASR（paraformer-zh） | `[{start_time, end_time, text}, ...]` |
| ASR 字级时间戳 | FunASR `timestamp` 字段 | `[[start_ms, end_ms], ...]`，每个汉字对应一个时间范围 |
| 知识点文字段 | LLM 一次调用返回 | `[{name, text}, ...]`，text 为原文截取，无时间戳 |
| 题目文字段 | LLM 一次调用返回 | `[{text}, ...]`，text 为原文截取，不区分题目/讲解 |

### 1.4 输出

| 输出 | 格式 | 用途 |
|---|---|---|
| 知识点起止时间 | `[{name, start_time, end_time, match_confidence}, ...]` | 知识点清单 + 知识点截图 |
| 题目起止时间 | `[{start_time, end_time, match_confidence}, ...]` | 题目截图 + 后续原题/解题分离 |
| 定位过程记录 | JSON | debug 分析，验证匹配准确性 |

## 三、步骤1：字符级时间戳映射表构建

### 3.1 数据来源

FunASR 的 `paraformer-zh` 模型在 `generate()` 返回结果中包含 `timestamp` 字段：

```python
result = self._model.generate(input=audio_path, batch_size_s=300)
text = result[0]["text"]           # 识别文本（带标点）
timestamp = result[0]["timestamp"]  # 字级时间戳 [[start_ms, end_ms], ...]
```

**注意**：`timestamp` 的长度对应**无标点的纯汉字**数量，而 `text` 包含标点。需要处理标点与字级时间戳的对应关系。

### 3.2 映射表结构

```python
# 字符级时间戳映射表
# 索引 = 字符在ASR长文本中的位置（包含标点）
# 值 = (start_ms, end_ms)
char_timestamp_map: List[Tuple[int, int]] = [
    (0, 320),      # 第0字 "同"
    (320, 640),    # 第1字 "学"
    (640, 960),    # 第2字 "们"
    (960, 1280),   # 第3字 "好"
    (1280, 1280),  # 第4字 "，"（标点，时间戳继承前一字的end_ms）
    ...
]
```

### 3.3 标点处理策略

标点符号在 FunASR 的 `timestamp` 中没有对应条目。处理方式：

- **标点的 start_ms = 前一个汉字的 end_ms**
- **标点的 end_ms = 后一个汉字的 start_ms**（如果后一个汉字存在）
- 如果标点在句末，end_ms = 前一个汉字的 end_ms

这样标点也有时间戳范围，便于精确匹配。

- [ ] 如果 `timestamp` 为空，降级策略是什么？（按句子时间戳 + 字符数线性估算？）

## 四、步骤2：两阶段模糊匹配

### 4.1 阶段A：n-gram 粗定位

#### 4.1.1 算法原理

将 ASR 长文本和 LLM 文字段都切成 **3-gram**（每3个连续字符一组），计算 n-gram 集合的 Jaccard 相似度：

```
similarity = |n-gram(A) ∩ n-gram(B)| / |n-gram(A) ∪ n-gram(B)|
```

在 ASR 长文本上**滑动窗口**，窗口长度 ≈ 文字段长度，计算每个窗口位置的相似度，取 top-3 候选位置。

#### 4.1.2 滑动窗口步长

- 步长 = 文字段长度的 10%（至少10个字符）
- 目的：减少计算量，同时保证不会错过匹配位置

#### 4.1.3 候选位置筛选

- 取相似度最高的 **3个** 候选位置
- 如果最高相似度 < 当前阈值（见步骤3），不进入精定位阶段

#### 4.1.4 为什么选3-gram

- 1-gram = 单字符，不考虑顺序，退化为Jaccard
- 2-gram = 双字符，考虑局部顺序，但对中文来说区分度不够
- 3-gram = 三字符，考虑了足够的局部顺序，计算量适中
- 4-gram以上：计算量增大，且对少量文字替换更敏感

**待确认**：3-gram是否最优？是否需要根据文字段长度动态调整n值？

### 4.2 阶段B：编辑距离精定位

#### 4.2.1 算法原理

在每个候选位置附近（±50字符范围），用**Levenshtein编辑距离**做精确比对，找到最佳的起始字符偏移和结束字符偏移。

编辑距离 = 将一个字符串转换为另一个字符串所需的最少插入、删除、替换次数。

#### 4.2.2 精定位范围

- 以候选位置为中心，向前扩展50字符，向后扩展50字符 + 文字段长度
- 在这个范围内计算编辑距离，找到最小距离对应的起始位置
- 结束位置 = 起始位置 + 文字段长度（允许±10字符微调）

#### 4.2.3 最佳匹配选择

- 对3个候选位置分别做精定位
- 取编辑距离最小的那个作为最终匹配结果
- 计算匹配置信度：`confidence = 1 - (edit_distance / max(len_text, len_segment))`

#### 4.2.4 待确认问题

- [ ] 编辑距离计算量：±50字符范围 × 文字段长度（几千字），是否需要优化？
- [ ] 是否用 Smith-Waterman 算法替代编辑距离？Smith-Waterman 能找到局部最优匹配，更适合处理插入删除，但计算量更大。
- [ ] 是否引入 `diff-match-patch` 库？Google优化的文本差异库，效率高。

## 五、步骤3：降阈值阶梯策略

### 5.1 阈值阶梯

| 轮次 | 相似度阈值 | 说明 |
|---|---|---|
| 第1轮 | **0.70** | 初始阈值，原文截取应该远高于此 |
| 第2轮 | **0.50** | 第1轮无候选时降阈值 |
| 第3轮 | **0.30** | 最低阈值，底线 |
| 低于0.30 | **触发方案B** | 关键词粗略定位兜底 |

### 5.2 方案B：关键词粗略定位

当3-gram相似度低于0.30时，使用关键词兜底：

1. 取 LLM 文字段的**前10个字符**作为关键词
2. 在 ASR 长文本中查找关键词第一次出现的位置
3. 如果找到：
   - 起始位置 = 关键词起始位置
   - 结束位置 = 起始位置 + 文字段长度
   - 匹配置信度标记为 `low`（关键词兜底）
4. 如果连关键词都找不到：
   - 标记该知识点/题目**定位失败**
   - 记录到 debug 日志
   - 跳过截图，不中断整体流程

### 5.3 待确认问题

- [ ] 阈值0.70/0.50/0.30是否合理？需要根据实际测试数据调整。
- [ ] 方案B的关键词取前10字是否合适？是否需要取前20字或第一句话？
- [ ] 关键词匹配是否也需要模糊匹配（允许1-2个字符差异）？

## 六、步骤4：顺序约束校验

### 6.1 约束原理

LLM 返回的知识点和题目应该**按时间顺序排列**。利用这个约束可以避免重复内容导致的误匹配。

### 6.2 约束规则

- 第 i 个文字段的匹配起始位置 **必须 ≥** 第 i-1 个文字段的匹配结束位置
- 如果不满足，说明可能匹配到了错误的位置（比如老师复习时重复讲了前面的内容）
- 处理方式：在第 i-1 个结束位置之后重新搜索，取之后的最佳匹配

### 6.3 允许重叠

- 相邻文字段允许少量重叠（比如一个的结尾和下一个的开头有交叉）
- 重叠阈值：允许重叠不超过文字段长度的20%
- 超过20%的重叠视为匹配错误，触发顺序约束重新搜索

### 6.4 待确认问题

- [ ] 顺序约束是否会导致误判？比如老师讲完知识点A后，回头补充了一句知识点A的内容，然后才开始知识点B。这种情况下知识点B的匹配位置应该在补充内容之后吗？
- [ ] 重叠阈值20%是否合理？

## 七、步骤5：查映射表得时间戳

### 7.1 时间戳计算

匹配完成后，得到文字段在ASR长文本中的起始字符索引 `start_char_idx` 和结束字符索引 `end_char_idx`。

查字符级时间戳映射表：

```python
start_ms = char_timestamp_map[start_char_idx][0]   # 起始字符的start_ms
end_ms = char_timestamp_map[end_char_idx][1]         # 结束字符的end_ms
start_time = start_ms / 1000.0   # 转换为秒
end_time = end_ms / 1000.0       # 转换为秒
```

### 7.2 边界处理

- 如果 `start_char_idx` 超出映射表范围，取映射表最后一个字符的时间戳
- 如果 `end_char_idx` 超出映射表范围，取映射表最后一个字符的时间戳
- 记录边界异常到 debug 日志

## 八、边界情况处理

### 8.1 重复内容

**场景**：老师在视频中重复讲类似内容（复习、总结）。

**对策**：
- 顺序约束（步骤4）确保按时间顺序匹配
- 取第一个满足顺序约束的匹配位置

### 8.2 文字段重叠

**场景**：两个相邻知识点的文字段有少量重叠。

**对策**：
- 允许重叠不超过20%
- 超过则触发顺序约束重新搜索

### 8.3 空文字段

**场景**：LLM 返回空的或极短的文字段（<10字符）。

**对策**：
- 文字段长度 < 10 字符，直接标记定位失败
- 记录到 debug，跳过截图

### 8.4 纠错改动太大

**场景**：LLM 纠错时把某段文字改得面目全非（小概率）。

**对策**：
- 降阈值阶梯（步骤3）逐步降低要求
- 最终用方案B关键词兜底

### 8.5 ASR字级时间戳缺失

**场景**：FunASR 未返回 `timestamp` 字段。

**对策**：
- 降级为句子级时间戳 + 字符数线性估算
- 记录降级警告到 debug
- **待确认**：线性估算公式：`char_time = sentence_start + (char_index_in_sentence / sentence_char_count) * sentence_duration`

## 十、性能估算

### 10.1 计算量

假设：
- ASR长文本：3万字
- 单个文字段：1000字
- 文字段数量：知识点10个 + 题目8个 = 18个

**阶段A（n-gram粗定位）**：
- 滑动窗口数 ≈ 30000 / (1000 * 0.1) = 300个窗口
- 每个窗口3-gram计算 ≈ O(1000)
- 总计 ≈ 300 * 1000 = 30万次操作 / 每个文字段
- 18个文字段 ≈ 540万次操作

**阶段B（编辑距离精定位）**：
- 每个候选 ±50字符范围 = 100 + 1000 = 1100字符
- 编辑距离 O(1100 * 1000) ≈ 110万次操作 / 每个候选
- 3个候选 ≈ 330万次操作 / 每个文字段
- 18个文字段 ≈ 5940万次操作

**总计**：约6500万次操作，Python实现可能需要几秒到十几秒。

### 10.2 优化方向

- [ ] n-gram粗定位用numpy向量化计算
- [ ] 编辑距离用C扩展库（如 `python-Levenshtein`）
- [ ] 多个文字段的粗定位可以并行（但精定位有顺序约束，需串行）
