# 教学视频提取与总结工具 — Windows 开发环境安装文档

> 适用系统：Windows 10 / 11（64位）
> 显卡：NVIDIA RTX 3080（10GB）
> 文档版本：v3.0（2026.08.23，纯云端多服务商架构，移除本地4090 vLLM，添加豆包API）
>
> **架构说明**：本机（3080）负责 FunASR 语音识别 + PaddleOCR 文字识别 + 主程序；大模型推理使用云端 API（豆包/DeepSeek），不再需要本地 4090 vLLM。

---

## v3.0 更新摘要（2026.08.23）

> **架构变更**：放弃本地 4090 vLLM 部署，改为纯云端多服务商架构。原因：4090 工作站电费 + 硬件折旧 > 云端 API token 费用，且本地 27B 模型推理质量不如云端。

| 变更项 | v2.2 旧版 | v3.0 新版 | 变更原因 |
|---|---|---|---|
| LLM 推理 | 本地 4090 vLLM + 云端 DeepSeek | **云端豆包 + DeepSeek（多服务商）** | 成本更低，质量更好 |
| 默认服务商 | DeepSeek | **豆包（volcengine）** | 中文同音词纠错效果优于 DeepSeek |
| ASR 纠错 | 无 | **豆包云端纠错** | 修正"地物→生物"等同音词错误 |
| 文本合并 | ASR + OCR 混合 | **纯 ASR（OCR 仅用于题目截图）** | OCR 混入导致语句逻辑混乱 |
| 颜色过滤 | 无 | **OCR 前去除彩色手写，只保留黑色印刷体** | 板书题目黑色，老师手写彩色 |
| Ollama | 可选 | **移除** | 不再需要本地 LLM 兜底 |
| 4090 部署文档 | 有 | **标记为废弃** | 不再使用 |

> **实际验证通过的版本组合**（2026.08.23，RTX 3080 Windows 11）：Python 3.11.9 + PyTorch 2.13.0+cu126 + CUDA Toolkit 12.0 + cuDNN 8.9.7 + PaddlePaddle 2.6.1.post120 + PaddleOCR 2.8.1 + FunASR 1.4.2 + opencv-contrib-python 4.10.0.84 + numpy 1.26.4 + openai 3.3.1，全部 GPU 可用，无依赖冲突。

## v2.2 更新摘要（2026.08.23）

> **重要修正**：PaddlePaddle Windows GPU 版**不自带** CUDA 运行时库，必须单独安装 CUDA Toolkit 12.0 + cuDNN 8.9.x。v2.1 文档中 CUDA Toolkit 仅作为"备选"是错误的，已修正为必装。

| 组件 | v2.1 旧版 | v2.2 新版 | 变更原因 |
|---|---|---|---|
| CUDA Toolkit | 12.6（备选） | **12.0（必装）** | PaddlePaddle 2.6.1.post120 基于 CUDA 12.0 编译，需要 cublas 等运行时库 |
| cuDNN | 未提及 | **8.9.7.29_cuda12（必装）** | PaddlePaddle GPU 推理必需，8.6.x 不兼容 CUDA 12.0 |
| PaddleOCR | 最新版（pip 自动解析） | **固定 2.8.1** | 3.x 要求 PaddlePaddle 3.x（Windows 无），2.8.1 是兼容 2.6.1 的最高版 |
| OpenCV | opencv-python | **opencv-contrib-python 4.10.0.84** | PaddleOCR 2.8.1 实际依赖 contrib 版，两者共存会冲突 |
| numpy | 无需锁定（支持 2.x） | **固定 1.26.4（<2.0）** | PaddleOCR 2.8.1 不兼容 numpy 2.x |
| stringzilla | 未提及 | **预编译 wheel 5.1.1** | PaddleOCR 2.x 依赖，Windows 无 VC++ 时需用 `--only-binary :all:` |
| PATH 策略 | 未提及 | **torch\lib → cuDNN → CUDA Toolkit** | 解决 PyTorch 自带 CUDA 与系统 CUDA Toolkit 的 DLL 冲突，代码已自动处理 |

> **实际验证通过的版本组合**（2026.08.23，RTX 3080 Windows 11）：Python 3.11.9 + PyTorch 2.13.0+cu126 + CUDA Toolkit 12.0 + cuDNN 8.9.7 + PaddlePaddle 2.6.1.post120 + PaddleOCR 2.8.1 + FunASR 1.4.2 + opencv-contrib-python 4.10.0.84 + numpy 1.26.4，全部 GPU 可用，无依赖冲突。

### 2.4 CUDA Toolkit 12.0（必装）

> **重要**：PaddlePaddle Windows GPU 版不自带 CUDA 运行时库，必须安装 CUDA Toolkit 提供 cublas 等 DLL。版本必须与 PaddlePaddle 编译时的 CUDA 版本一致（12.0）。

#### 下载
- 官网：https://developer.nvidia.com/cuda-12-0-0-download-archive
- 选择：Windows → x86_64 → 10/11 → exe (local)
- 下载文件：`cuda_12.0.0_528.33_windows.exe`（约 3GB）

#### 安装步骤
1. 双击运行安装程序
2. 选择「自定义（高级）」安装
3. 只勾选以下组件（其余取消勾选，避免装多余东西）：
   - `CUDA` → `Runtime` → 全部子项（含 Libraries、Development 等）
   - **取消勾选** `Driver components`（你已有显卡驱动，不需要重装）
   - **取消勾选** `Visual Studio Integration`（如不需要）
4. 点击下一步，等待安装完成

#### 安装位置
- 默认：`C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.0\`

#### 环境变量
- 安装程序自动配置：
  - `CUDA_PATH` = `C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.0`
  - `Path` 中自动添加 `%CUDA_PATH%\bin`

#### 验证
**重启 PowerShell**后输入：
```powershell
nvcc --version
# 期望：release 12.0

where.exe cublas64_12.dll
# 期望：找到 C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.0\bin\cublas64_12.dll
```

### 2.5 cuDNN 8.9.7.29_cuda12（必装）

> **重要**：cuDNN 版本必须与 CUDA Toolkit 版本匹配。CUDA 12.0 用 cuDNN 8.9.x。**cuDNN 8.6.x 不兼容 CUDA 12.0**，会导致 PaddlePaddle 进程崩溃（0xC0000409）。

#### 下载
- 官网下载列表：https://developer.nvidia.com/cudnn
- 或直接下载（需 NVIDIA 账号登录）：
  ```
  https://developer.download.nvidia.com/compute/cudnn/redist/cudnn/windows-x86_64/cudnn-windows-x86_64-8.9.7.29_cuda12-archive.zip
  ```
- 文件大小：约 676MB

#### 安装步骤
1. 解压下载的 zip 文件
2. 将解压后的文件夹重命名为 `cudnn`
3. 移动到 `C:\tools\cudnn\`（最终目录结构：`C:\tools\cudnn\bin\cudnn64_8.dll`）

#### 目录结构
```
C:\tools\cudnn\
├── bin\
│   ├── cudnn64_8.dll
│   ├── cudnn_adv_infer64_8.dll
│   ├── cudnn_cnn_infer64_8.dll
│   └── ...
├── include\
│   └── cudnn*.h
└── lib\
    └── x64\
        └── cudnn*.lib
```

#### 环境变量
将 `C:\tools\cudnn\bin` 添加到系统 `Path`。

> **可选**：设置环境变量 `CUDNN_PATH` = `C:\tools\cudnn\bin`，项目代码会优先读取此变量。

#### 验证
```powershell
where.exe cudnn64_8.dll
# 期望：找到 C:\tools\cudnn\bin\cudnn64_8.dll
```

### 2.6 云端 LLM API 配置（豆包 / DeepSeek）

> 本项目使用云端 LLM API 进行知识点提取、题目提取、思维导图生成和 ASR 纠错。支持多服务商，默认使用豆包（中文纠错效果更好）。

#### 豆包（火山引擎）— 默认推荐

1. 注册火山引擎账号：https://www.volcengine.com/
2. 进入火山方舟控制台：https://ai.volcengine.com/
3. 开通"语言、图像、视频模型"服务
4. 创建 API Key（左侧导航栏 → API Key 管理 → 创建）
5. 在项目根目录 `.env` 文件中添加：
   ```ini
   VOLCENGINE_API_KEY=你的火山引擎API_Key
   VOLCENGINE_MODEL=doubao-seed-2-1-pro-260628
   VOLCENGINE_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
   ```

> **注意**：豆包模型名必须带日期后缀（如 `doubao-seed-2-1-pro-260628`），不能用简写。使用 `responses.create` 接口（非 `chat.completions`），需禁用思考过程 `reasoning={"effort": "none"}`。

#### DeepSeek — 备选服务商

1. 注册 DeepSeek 账号：https://platform.deepseek.com/
2. 创建 API Key
3. 在项目根目录 `.env` 文件中添加：
   ```ini
   DEEPSEEK_API_KEY=sk-你的DeepSeek_API_Key
   DEEPSEEK_MODEL=deepseek-v4-flash
   DEEPSEEK_BASE_URL=https://api.deepseek.com
   ```

> **注意**：DeepSeek 需禁用思考过程 `extra_body={"thinking": {"type": "disabled"}}`，否则 token 会被思考过程占满。

#### 切换默认服务商

在 `config.yaml` 中修改：
```yaml
llm:
  default_provider: volcengine  # volcengine=豆包, deepseek=DeepSeek
```

## 四、PATH 共存策略（PyTorch + PaddlePaddle）

### 4.1 问题背景

本项目同时使用 PyTorch（FunASR）和 PaddlePaddle（PaddleOCR）两个深度学习框架：

- **PyTorch** 自带 CUDA 运行时库（位于 `venv\Lib\site-packages\torch\lib\`），包括 cublas、cudnn 等
- **PaddlePaddle** 不自带 CUDA 运行时库，依赖系统安装的 CUDA Toolkit + cuDNN

如果系统 PATH 中 CUDA Toolkit 的 `cublas64_12.dll` 优先于 PyTorch 自带的版本，PyTorch 加载时会因版本不匹配而报错（`Error loading shm.dll`）。

### 4.2 解决方案：PATH 顺序

必须按以下顺序设置 PATH（优先级从高到低）：

```
1. venv\Lib\site-packages\torch\lib   ← PyTorch 自带 CUDA 库，优先加载
2. C:\tools\cudnn\bin                  ← cuDNN 8.9.x（PaddlePaddle 需要）
3. C:\Program Files\...\CUDA\v12.0\bin ← CUDA Toolkit（cublas 等，PaddlePaddle 需要）
4. 原有系统 PATH
```

### 4.3 代码自动处理

项目 `main.py` 已内置 `_setup_windows_gpu_path()` 函数，在 import torch/paddle 之前自动设置 PATH，无需手动配置。

支持环境变量覆盖：
- `CUDNN_PATH`：cuDNN bin 目录（默认 `C:\tools\cudnn\bin`）
- `CUDA_PATH`：CUDA Toolkit bin 目录（默认 `C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.0\bin`）

### 4.4 验证三者共存

```powershell
python -c "import torch; print('torch:', torch.__version__, 'CUDA:', torch.cuda.is_available()); import paddle; print('paddle:', paddle.__version__); import funasr; print('funasr:', funasr.__version__); from paddleocr import PaddleOCR; print('ALL OK')"
```

期望全部输出，无报错。

## 七、依赖冲突风险与规避

| 冲突点 | 风险 | 说明 | 应对策略 |
|---|---|---|---|
| **numpy 版本** | 高 | PaddleOCR 2.8.1 不兼容 numpy 2.x，必须 <2.0 | 固定 `numpy==1.26.4`，安装 PaddleOCR 时 pip 会自动降级 |
| **OpenCV 版本** | 高 | `opencv-python` 与 `opencv-contrib-python` 共存会导致 cv2 冲突 | 只装 `opencv-contrib-python==4.10.0.84`，不装普通版 |
| **PaddleOCR 版本** | 高 | 3.x 要求 PaddlePaddle 3.x（Windows 无） | 固定 `paddleocr==2.8.1` |
| **CUDA runtime 共存** | 高 | PyTorch 自带 CUDA 12.6，系统 CUDA Toolkit 12.0，DLL 搜索顺序错误会导致 PyTorch 加载失败 | PATH 顺序：torch\lib → cuDNN → CUDA Toolkit，代码已自动处理 |
| **cuDNN 版本** | 高 | cuDNN 8.6.x 不兼容 CUDA 12.0，会导致 PaddlePaddle 进程崩溃（0xC0000409） | 必须用 cuDNN 8.9.x_cuda12 |
| **stringzilla 编译** | 中 | PaddleOCR 2.x 依赖，Windows 默认从源码编译需 VC++ | 用 `pip install stringzilla --only-binary :all:` 装预编译版 |
| **PaddlePaddle Windows 版本限制** | 中 | 3.x 仅 Linux，Windows 最高 2.6.1 | 固定 `paddlepaddle-gpu==2.6.1.post120` |
| **protobuf 版本** | 低 | FunASR 与 PaddlePaddle 都依赖 protobuf | 全部安装完成后 `pip show protobuf` 确认 |

## 九、严格安装顺序

**必须按以下顺序安装，最大限度减少依赖冲突：**

```
1. 系统软件：Python 3.11 → ffmpeg → Git → CUDA Toolkit 12.0 → cuDNN 8.9.7
2. 创建 venv → 激活
3. 安装 PyTorch 2.13.0+cu126（指定 --index-url）
4. 安装 PaddlePaddle-gpu==2.6.1.post120（指定飞桨源）
5. 安装 stringzilla --only-binary :all:（预编译，避免 VC++ 编译）
6. 安装 PaddleOCR==2.8.1（pip 会自动降级 numpy 到 1.26.4，安装 opencv-contrib-python）
7. 确认卸载 opencv-python（普通版），只保留 contrib 版
8. 安装 FunASR==1.4.2 + modelscope
9. 安装 openai
10. 执行第六章全部验证
11. 锁定全量版本：pip freeze > requirements.txt
```

**原理**：先装两个大框架（PyTorch、PaddlePaddle），它们对 numpy/protobuf 等底层依赖有严格版本要求；上层库后装，在已有约束下解析，冲突概率最低。

## 十、Windows 平台注意事项

| 问题 | 影响 | 应对 |
|---|---|---|
| **默认编码 GBK** | Python 读写中文文件可能乱码 | 代码中统一 `encoding='utf-8'`；PowerShell 执行 `chcp 65001` |
| **路径长度 260 限制** | venv 嵌套深 + 模型缓存路径长可能报错 | 虚拟环境放在短路径；如需启用长路径，以管理员执行 `reg add HKLM\SYSTEM\CurrentControlSet\Control\FileSystem /v LongPathsEnabled /t REG_DWORD /d 1 /f`，然后重启 |
| **PowerShell 执行策略** | venv 激活脚本被禁止运行 | 以管理员执行 `Set-ExecutionPolicy RemoteSigned` |
| **CUDA Toolkit 安装后 PATH 未刷新** | 当前 PowerShell 会话找不到 nvcc | 关闭所有 PowerShell 窗口，重新打开 |
| **防火墙** | 云端 API 调用可能被拦截 | 首次通信时防火墙弹窗选择「允许」 |
